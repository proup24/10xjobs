# Ingest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Store shared normalized jobs with source identity deduplication and lookup-query attribution.
**Architecture:** Pure normalization feeds a Nest service and transactional Prisma repository. Identity aliases resolve source IDs and canonical URLs; ATS identities associate observations across channels.
**Tech Stack:** NestJS, TypeScript, Prisma 8 PostgreSQL contract, Vitest.
**Spec:** `docs/superpowers/specs/2026-10-30-ingest-design.md`

## Global Constraints

- No user/profile ownership on raw jobs; existing query rows remain lookup references.
- No title/company deduplication, paid calls, inferred job facts or remote database migrations.
- Item-level transactions, chronological updates, conservative URL handling and original JSON preservation.

## Review Focus

- A URL-only observation later gains a source ID: same row, no duplicate.
- Different source IDs claim the same URL: explicit conflict, no partial write.
- Concurrent queries and stale snapshots: attribution survives without content regression.
- Social authors and HTML: no invented employer or script content in normalized text.
- Migration history predates current ownership: additive ingest delta must not silently drop old tables.
